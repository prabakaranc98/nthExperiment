# Self-Correction / Reflection

**One-liner:** A model critiques and revises its own output across one or more passes; reliably helpful when the critique is grounded in external/ground-truth feedback (tests, verifier, execution), but frequently a no-op or net-negative when purely intrinsic — the SCoRe-relitigated finding.

## The key insight

Two-stage loop: `y0 = M(x)`, then `c = M(critique | x, y0)`, then `y1 = M(revise | x, y0, c)`, optionally iterated. The gain decomposes into the **error-detection** step (can the model localize its own mistakes?) and the **error-correction** step (can it fix them once told where?). Intrinsic self-correction asks the *same* model, with no new information, to do both — and detection is the bottleneck: the model has no signal it didn't already condition on, so it often "corrects" right answers into wrong ones (over-revision) and stays anchored on confident errors.

- **Extrinsic / grounded** (works): feedback `c` comes from outside the model's beliefs — unit tests, a compiler, a search result, a stronger verifier, a reward model, oracle "is this correct?" labels. This is the regime where Reflexion-style loops and agentic debugging deliver real gains.
- **Intrinsic** (unreliable): `c` is generated by the same model with no external grounding. Huang et al. (2024, "Large Language Models Cannot Self-Correct Reasoning Yet") showed apparent gains vanish or reverse once you control for oracle stopping criteria.

**SCoRe (Kumar et al., 2024)** fixed intrinsic self-correction not via prompting but via **multi-turn RL**: reward the *delta* (second-attempt minus first-attempt correctness) with a regularizer pinning the first attempt near the base policy, preventing the model from collapsing to "just don't change anything" or "always rewrite." First method to get positive intrinsic self-correction on MATH/HumanEval from self-generated data alone.

## Where it appears

- **Reflexion (Shinn et al., 2023)** — verbal self-reflection stored in episodic memory between trials; gains come from the *environment* signal (test pass/fail, task reward), i.e. extrinsic.
- **SCoRe (DeepMind, 2024)** — RL-trains intrinsic self-correction with a two-turn reward shaping + KL pin to base; the canonical "make reflection actually work" result.
- **Self-Refine (Madaan et al., 2023)** — iterative self-feedback; strong on open-ended generation (style, formatting), weaker on hard reasoning where detection fails.
- **CriticGPT / verifier-in-the-loop agents** — a separate critic model or executable check supplies grounded feedback; o1/o3/R1-style long CoT internalizes backtracking ("wait, that's wrong") into a single pass rather than an explicit second call.

## Common mistake

Reporting self-correction gains using an **oracle stopping criterion** — "keep revising until the answer is correct" or "only revise if the first answer was wrong." That smuggles in ground-truth labels the deployed system won't have; under fair (model-decided) stopping, intrinsic self-correction on reasoning is often flat or negative. Always ask: where did the correction signal come from, and was it available without the answer key?
